# Issues Found in `blood_donation.py`

Found with Pylint, Bandit and Flake8 (reports are generated by
`run_analysis.sh`) and by reading the code. Line numbers refer to the
**original** file. High and medium severity are listed first.

| Issue | Type | Line(s) | Description | Fix Approach |
|-------|------|---------|-------------|--------------|
| Hard-coded password (Bandit B105, High/Medium) | Security | 5 | `OFFICER_PASSWORD = "bloodbank-demo"` stores a secret in source code, so anyone with repo access can read it. It is also never used. | Read it from an environment variable (`os.environ.get("BLOODBANK_OFFICER_PASSWORD")`) so no secret is committed. |
| OS command injection via `os.system` (Bandit B605/B607, High) | Security | 67 | `os.system("send-sms " + " ".join(phoneList))` builds a shell command from input. A value such as `123; rm -rf ~` would run extra commands. | Validate each number with a regex and call `subprocess.run(["send-sms", *phones], check=True, shell=False)` so no shell is involved. |
| Insecure temporary file `tempfile.mktemp` (Bandit B306, Medium) | Security | 62 | `mktemp` only returns a name; another process can create or link that file before it is opened (race condition / symlink attack). | Use `tempfile.mkstemp`, which creates the file atomically with safe permissions, and close the descriptor. |
| `assert` used for input validation (Bandit B101, Low) | Security / Bug | 21 | Asserts are removed when Python runs with `-O`, so an invalid blood group would silently be accepted and later raise a `KeyError`. | Replace with an explicit `if ... : raise ValueError(...)`. |
| Mutable default argument `notes=[]` (Pylint W0102) | Bug | 20-23 | The same list is shared between every call, so messages pile up across calls and the parameter leaks state. The caller never sees the list anyway. | Remove the parameter, report the reason with `logging`, and keep the `True`/`False` return value. |
| Incomplete `COMPATIBLE` table hides wrong results | Logic bug | 11-17, 45-50 | `A-`, `B-` and `AB-` have no entry, so `unitsFor("AB-")` returns 0 even when compatible units exist. The blanket `except Exception` hides the resulting `KeyError`. | Add the missing groups to `COMPATIBLE` and use `COMPATIBLE.get(patient_group, [])` instead of exception handling. |
| Overly broad `except Exception` (Pylint W0718) | Quality | 47-49 | Catches every error, including real bugs, and returns 0, which makes failures look like "no stock". | Remove the `try/except`; handle the only expected case (unknown group) with `.get()`. |
| No validation of `units` in `recordDonation` | Bug | 36-42 | Zero or negative units would silently reduce or corrupt stock. | Raise `ValueError` when `units <= 0`. |
| Code runs on import: `main()` at module level | Design | 86 | Importing the file (for tests or reuse) immediately runs the demo and mutates global state. | Wrap the call in `if __name__ == "__main__":`. |
| Non-snake_case names (Pylint C0103) | Style | 20, 30, 36, 45, 52, 56, 60, 65 and their parameters | `registerDonor`, `canDonate`, `bloodGroup`, `phoneList` etc. break PEP 8 naming. Module-level `donors` and `stock` are mutable constants named in lower case. | Rename to `register_donor`, `can_donate`, `blood_group`, `phone_list`, ...; rename globals to `DONORS` and `STOCK`. |
| Missing docstrings (Pylint C0114, C0116) | Documentation | 1, every function | No module or function documents what it does, its arguments or its return value. | Add a module docstring and a short docstring to every function. |
| Composite comparison (Pylint R1714) | Quality | 53 | `bloodGroup == "O-" or bloodGroup == "AB+"` repeats the variable. | Use `blood_group in ("O-", "AB+")`. |
| Magic numbers 18, 65, 90 | Maintainability | 22, 34 | Eligibility rules are buried in the logic and hard to change or explain. | Move them into named constants `MIN_AGE`, `MAX_AGE`, `DONATION_GAP_DAYS`. |
| Missing whitespace around `=` (Flake8 E225) | Style | 83 | `eligible=[...]` is not PEP 8 formatted. | Write `eligible = [...]`. |
| Expected 2 blank lines after function (Flake8 E305) | Style | 86 | Only one blank line separates `main()` from the preceding code. | Add two blank lines (and the `__main__` guard). |
